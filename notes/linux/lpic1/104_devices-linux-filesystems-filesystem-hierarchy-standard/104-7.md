# Find System Files and Place Files in the Correct Location

## FHS - File System Hierarchy

File system hierarchy is a standard which defines and describe a set of requirements and
guidelines for file and directory placement in Unix-like systems.

Check the
[Design Hard Disk Layout](../102_linux-installation-and-package-management/102-1.md)
lesson. We covered FHS in that lesson too. But let's revisit and expand our
understanding from filesystem.

| directory      | purpose                                                                                                                                                                 |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| /              | Primary hierarchy root directory of the entire file system hierarchy. Everything falls under this place.                                                                |
| /run           | This directory contains information which describes the system since it was booted. Once this purpose was served by `/var/run`.                                         |
| /bin           | This directory contains executable programs which are needed in single user mode and to bring the system up or repair it.                                               |
| /boot          | Contains static files for the bootloader. This directory hold on files needed during boot process.                                                                      |
| /dev           | Special or device files, which refer to physical devices.                                                                                                               |
| /etc           | Contains configuration files that are local to the machine. Site-wide programs may put their configuration here or `/usr/etc`.                                          |
| /etc/skel      | When a new user is created, the files in this directory are usually copied to the user's home directory.                                                                |
| /home          | Store home directories. The structure of this directory depends on local administration decisions.                                                                      |
| /lib           | Hold shared libraries that are necessary to boot the system and run commands in the root file system.                                                                   |
| /lib/modules   | Loadable kernel modules.                                                                                                                                                |
| /lost+found    | Contain lost files on the file system.                                                                                                                                  |
| /media         | The directory serves as the mount point of removable media such as CD and DVD disks or USB sticks.                                                                      |
| /mnt           | This directory is a mount point for temporarily(?) filesystem.                                                                                                          |
| /opt           | The directory should contain add-on packages that contain static files.                                                                                                 |
| /proc          | Mount point for the `proc` file system. It provide information about running processes and the kernel.                                                                  |
| /root          | Usually it is a home directory of the root user.                                                                                                                        |
| /srv           | Contains site-specific data that is served by this system.                                                                                                              |
| /tmp           | Store temporary files which may be deleted without notice, such as by regular jobs or at system boot up.                                                                |
| /usr           | It should hold only sharable, read-only data, so that it can be mounted by various machines running Linux. This directory is usually mounted from a separate partition. |
| /usr/bin       | Primary directory for storing executable programs. Most programs run by normal users which are not used during repair or single-user mode are stored here.              |
| /usr/sbin      | Primary directory for storing binaries for system administration which are not essential for the boot process, system repair, or mounting /usr.                         |
| /usr/local     | This is where the programs that are local to the site usually go.                                                                                                       |
| /usr/share     | This directory contains subdirectories with specific application data, that can be shared among different architectures of the same OS.                                 |
| /var           | This directory contains files that may change in size, such as spool and log files.                                                                                     |
| /var/cache     | Data cached for programs.                                                                                                                                               |
| /var/cache/www | WWW proxy or cache data.                                                                                                                                                |
| /var/lock      | Lock files are stored in this directory.                                                                                                                                |
| /var/log       | Miscellaneous log files.                                                                                                                                                |
| /var/opt       | Variable data for `/opt`.                                                                                                                                               |
| /var/spool     | Spooled or queued files for various programs.                                                                                                                           |
| /var/tmp       | Like /tmp, this directory contains temporary files for an unspecified duration.                                                                                         |

> :mag: You can always read about file system hierarchy using `man hier`.

**The map installer and configuration of booting should go to `/sbin` and `/etc`.**

> :bulb: The `/usr` is the second level of hierarchy. It can be shared between systems
> but the present practice does not often do this.

## Finding Files

First of all, I have 6,520,315 files on my system, how Linux know where to find and run
the commands? As I said before, using `PATH` environment variable.

```bash
ali> echo $PATH
/usr/local/mongodb/bin:/usr/local/mongodb/bin:/home/ali/.local/bin:/usr/local/sbin:...

ali> sudo su

root> echo $PATH
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:...

root> cat ~/.bashrc | grep -i PATH:

root> cat ~/.bashrc | grep -i PATH

root> exit
exit

ali> cat ~/.bashrc | grep PATH
export PATH="$PATH:/home/ali/.local/bin"
export PATH=/usr/local/mongodb/bin:$PATH
export PATH=/usr/local/mongodb/bin:$PATH
```

### which

`which` command shows the first appearance of the command in the `PATH`. In other words,
`which mkfs` will tell you which executable program is going to run when entering the
`mkfs` command.

### whereis

Shows the source, binary, and manual pages for the command.

### type

`type` is more general than which and specify what is the command that is applied.

```bash
which ping
/usr/bin/ping

which -a ping
/usr/bin/ping
/bin/ping

whereis ping
ping: /usr/bin/ping /usr/share/man/man8/ping.8.gz

type ping
ping is /usr/bin/ping

type cd
cd is a shell builtin
```

### whatis

Display one-line manual page descriptions.

```bash
whatis ping
ping (8)             - send ICMP ECHO_REQUEST to network hosts
```

## find New Switches

- The `-user` and the `-group` specify a user and group.
- The `-maxdepth` tells the find how deep it should go into directories.

```bash
find / ! -user ali ! -user root -maxdepth 4 2> /dev/null
/dev/shm/PostgreSQL.592978984
/dev/tpmrm0
/dev/tpm0
/etc/postgresql
/etc/postgresql/14
/etc/postgresql/14/main
/etc/redis
```

Or you can use `-nouser` or `-nogroup`.

## locate and updatedb

`find` does a live active search. This can slow down the system. A mechanism is
implemented in Linux where, a database is updated once a day using a cron job, which
will store all the file names of the system. `locate` command will use that db, and you
can manually update the db using `updatedb` command. `locate` is usually a better choice
when you want to find a file containing a matching string.

```bash
ali> time locate starlette | wc -l
587

real  0m0.014s
user  0m0.008s
sys 0m0.008s

ali> updatedb
/var/lib/plocate/: Permission denied
sudo updatedb
[sudo] password for ali:

ali> cat /etc/updatedb.conf
PRUNE_BIND_MOUNTS="yes"
# PRUNENAMES=".git .bzr .hg .svn"
...
```

> The configuration files of `updatedb` are under `/etc/updatedb.conf` and
> /etc/sysconfig/locate/\`.
