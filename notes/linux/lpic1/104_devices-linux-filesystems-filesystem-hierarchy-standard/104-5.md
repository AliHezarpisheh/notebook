# Manage File Permissions and Ownership

## Users and Groups

In linux, users represents individual accounts representing a person or service, while
groups are collection of users that simplify access control and permission management
for shared files and resources.

Each user belongs to a primary group and can be members of other groups(called secondary
groups).

```bash
whoami
ali

groups
ali adm cdrom sudo dip plugdev lpadmin lxd sambashare docker

id
uid=1000(ali) gid=1000(ali) groups=1000(ali),4(adm),24(cdrom),27(sudo),30(dip),
46(plugdev),122(lpadmin),135(lxd),136(sambashare),999(docker)

cat /etc/passwd | grep -E "ali|postgres|redis"
ali:x:1000:1000:ali,,,:/home/ali:/bin/bash
postgres:x:129:137:PostgreSQL administrator,,,:/var/lib/postgresql:/bin/bash
redis:x:130:138::/var/lib/redis:/usr/sbin/nologin

cat /etc/group
root:x:0:
daemon:x:1:
bin:x:2:
sys:x:3:
adm:x:4:syslog,ali
tty:x:5:
disk:x:6:
```

> uid `0` and gid `0` belong to the root user and group.

### Permissions

Permission are the `rights` to act on a file or directory(in linux context). There are
three basic permissions:

- Read: Let the contents to be viewed. For a directory, it means you can list the
  contents inside it.
- Write: Let you to modify contents of a file. For a directory, it means you can edit
  the contents in the directory.
- Execute: Let you to run and execute the file. For a directory, it let's you to change
  directory to it.

### File Ownership and Permission

Linux uses three layers for access/permission for each file and directory: User, Group,
and Others.

Each file belongs to one user and one group. Let's look at how the permissions are
displayed:

```bash
ls -lrth
total 37M
-rw-rw-r-- 1 ali ali 8.9M Nov 21  2023 'Python Testing with pytest_ Simple, ....pdf'
```

- `ali` user is the owner of the file. The file also belongs to `ali` group.
- The other 9 characters display the user permissions. I believe the picture below
  speaks for itself.

![Linux Permissions](./photos/permissions.png)

> In many distros, when you create a user, the system creates a group with the same name
> and assigns that user's files to that group.

## Changing Permissions

### chmod

`chmod` is the main command for changing permissions on files and directories. There are
two ways to tell the command what permissions you want to set:

- Using octal codes.
  - read(r): 4
  - write(w): 2
  - execute(x): 1
- Using short codes.
  - r,w,x

You have to sum up the numbers of the permissions you want to set for the file or dir.
For example, if you want to set a file readable and executable, do `4 + 1 = 5`.

Actually, chmod set permissions for users, groups, and others. Let's look at some
examples.

```bash
ls -ltrh myfile
-rw-rw-r-- 1 jadi jadi 0 Feb  8 21:01 myfile

chmod 751 myfile

ls -ltrh myfile
-rwxr-x--x 1 jadi jadi 0 Feb  8 21:01 myfile
```

Use `755` for general executable files and `600` for personal files.

Let's look at some examples using short codes:

```bash
ls -ltrh myfile
-rwxr-x--x 1 jadi jadi 0 Feb  8 21:01 myfile

chmod u-x myfile

ls -ltrh myfile
-rw-r-x--x 1 jadi jadi 0 Feb  8 21:01 myfile

chmod +x myfile

chmod uo+xr myfile

ls -ltrh myfile
-rwxr-xr-x 1 jadi jadi 0 Feb  8 21:01 myfile
```

> Use `-R` switch with caution. It will give the permissions recursively to all the
> files and directories.

## Changing Owner and Groups

If you want to change the ownership or group of a file or directory, use the `chown`
command.

```bash

touch file.txt

ls -lrth file.txt
-rw-r--r-- 1 root root 0 Dec 29 20:47 file.txt

chown ali:ali^C

exit
exit

cd /tmp/

rm file.txt
rm: remove write-protected regular empty file 'file.txt'? y
rm: cannot remove 'file.txt': Operation not permitted

su
Password:
su: Authentication failure

su
Password:
^C

sudo su

chown ali:ali file.txt

exit
exit

rm file.txt
```

> chown has a `-R` switch too.

If you want to just change the group, use `chgrp`.

```bash
sudo chgrp postgres newfile
ls -ltrh newfile
-rw-rw-r-- 1 root postgres 0 Feb  8 21:38 newfile
```

Add users to new groups using `usermod -aG` command.

```bash
sudo usermod -aG postgres ali
```

With `newgrp` you can set the default group of a user.

```bash
newgrp adm
```

## Access Modes

There is an interesting question, let's observe the /etc/passwd and /etc/shadow
permissions:

```bash
ls -lrth /etc/passwd /etc/shadow
-rw-r--r-- 1 root root   3.0K Nov 24 11:19 /etc/passwd
-rw-r----- 1 root shadow 1.6K Nov 24 11:19 /etc/shadow
```

As you can see, no one but roo can not modify these files. So how can we change our
password using passwd command? Let's see the permission bits of the passwd executable:

```bash
which passwd | xargs ls -lrth
-rwsr-xr-x 1 root root 59K Feb  6  2024 /usr/bin/passwd
```

You can see a `s` bit instead of `x` or `-`. So what does it mean? suid(set user id) and
sgid(set group id) are the bits that let the file be executed with the access of the
owner not the user executing it.

Use `chmod +s` or `chmod -s` to set or unset this bit.

There is also a `sticky bit` which will make files resistant to deletion.

```bash
ls -dl /tmp
drwxrwxrwt 13 root root 77824 Feb  8 21:27 /tmp
```

Let's have a review on the last three bits:

| Access Mode | Octal Value | Symbolic Notation |
| ----------- | ----------- | ----------------- |
| SUID        | 4000        | u+s               |
| SGID        | 2000        | g+s               |
| Sticky      | 1000        | +t                |

## umask

`umask` set the default permissions of a newly created file. Actually this command tells
the system which permissions should not be set for the file. The umask get 4 digits,
which you should subtract to `666`.

```bash
ls -lrth xaa
-rw-rw-r-- 1 ali ali 218 Dec 29 15:12 xaa

umask
0002

umask 0444

rm xaa

touch xaa

ls -lrth xaa
--w--w--w- 1 ali ali 0 Dec 29 21:08 xaa

umask u=rw,g=,o=
```
