# Create and Change Hard and Symbolic(Soft) Links

## Links

First of all, you have to understand how files are created in linux filesystems. When
you create a file on the file system, the kernel will create a corresponding inode for
the file. The inode holds metadata(such as permissions, timestamps, size) and crucially,
the data block addresses. This is a great example of separation of concerns, you see,
the kernel separates the file metadata and data as two distinctive entities to manage.

When you create a file, you are creating a directory entry(dentry).

### Directory Entry

Directory entries are the actual records stored inside a directory file. Think of a
directory as a table with two columns: one column holds the name of the filenames(like
photo.jpg or documents/(yes, directories are files too)), and one holding the
corresponding inode number. Each row in the table is the directory entry. When you
execute `ls`, you are telling to kernel to read the directory entries and print out the
filenames. When you want to open a file by name, the kernel scans thought the directory
entries looking for the matching name, then extracts the inode number from that entry.

#### Path Resolution/Pathname Lookup

Say you have a file on `/home/ali/file.txt`. The kernel starts at the root directory,
which has a well-known inode number(typically 2 in ext4 filesystems). The inode points
to the data blocks that contain directory entries. The kernel scans the entries looking
for `home`. That inode points to the data block that contains more directory entries.
The kernel will look for a directory entry with filename `ali`. Then it reads the ali
directory entries and then finds the `file.txt` mapping to a specific inode. Finally the
kernel opens that inode and read the data block. This process is called path resolution
or pathname lookup.

> :bulb: So each directory is actually a special file whose data happens to be formed as
> a table of directory entries.

Now we can jump into hard links and soft links, knowing the fundamentals. There are two
ways to link files in Linux systems.

### Hard Links

Hard links are additional directory entries, pointing to the same inode as their
original file.

Use `ln` command without the `-s` switch to create hard links.

> File that are hard linked share the same inode number. Use `ls -i` to view the inode
> numbers.

**Hard links can only be applied to normal files(not directories or special files).
Also, they can not span on multiple file systems.**

They can not be applied on different file systems, because every file system has its own
inode table. Also, we can not hard link directories, because this can possibly create
cycles on the directory tree, leading to broking filesystem traversal algorithm.
However, we can hard link `.` and `..`.

```bash
touch a.txt

ls -lrth a.txt
-rw-rw-r-- 1 ali ali 0 Jan  1 14:18 a.txt

ln a.txt /tmp/mioo.txt

ls -lrth /tmp/mioo.txt
-rw-rw-r-- 2 ali ali 0 Jan  1 14:18 /tmp/mioo.txt

echo "Hi" >> a.txt

cat a.txt
Hi

cat /tmp/mioo.txt
Hi

unlink a.txt

cat /tmp/mioo.txt
Hi

ls -lrth /tmp/mioo.txt
-rw-rw-r-- 1 ali ali 3 Jan  1 14:19 /tmp/mioo.txt

unlink /tmp/mioo.txt
ls /tmp/mioo.txt
ls: cannot access '/tmp/mioo.txt': No such file or directory
```

### Soft Links

Actually, a soft link is not a standard file, it is a special file which points to an
existing file.

A symlink actually holds and have its own inode that contains a special file type flag.
Instead of pointing to data blocks containing regular file contents, the symlink's inode
points to data blocks that contains a text string, a path to another file. When the
kernel encounters a symlink during path resolution, it reads the path string and
continues the lookup from there.

A symlink's inode can point to any path. The path could be on another file system, it
even the path can not exist.

Use `ln` command with the `-s` switch to create hard links.

**If the original file is deleted, the soft link is broken and the data is lost. This is
referred as a dangling soft link. If you create a file with the same name as the
original deleted file, the link is not dangling anymore.**

```bash
which python3
/usr/bin/python3

readlink -f /usr/bin/python3
/usr/bin/python

cd /usr/bin/

ls python*
python3     python3.10-config  python3.12  python3.14      python3-futurize
python-argcomplete-check-easy-install-script3  python-dotenv python3.10  python3.11
python3.13  python3-config  python3-pasteurize  python-argcomplete-tcsh3

ln -s python3 python  # It is like copy.
ln: failed to create symbolic link 'python': Permission denied

ls -lrth python3
lrwxrwxrwx 1 root root 10 Sep 16  2024 python3 -> python3.10

sudo ln -s python3 python
[sudo] password for ali:

python
Python 3.10.12 (main, Nov  4 2025, 08:48:33) [GCC 11.4.0] on linux
Type "help", "copyright", "credits" or "license" for more information.
>>>
```

> It is recommended to use the exact paths for links.

We can use `find . -type l` to find symbolic links on the system.

A famous use case for symlink usage is holding a specific name pointing to a changing
binary name. Like the thing I had done in the above example with `python`.

To remove links, you can use the `rm` or `unlink` commands.

```bash
sudo unlink /usr/bin/python
[sudo] password for ali:

python
bash: /usr/bin/python: No such file or directory

sudo ln /usr/bin/python3 /usr/bin/python

python
Python 3.10.12 (main, Nov  4 2025, 08:48:33) [GCC 11.4.0] on linux
Type "help", "copyright", "credits" or "license" for more information.
>>>
```

> Hard links can be more efficient in the performance perspective. Do you know why:)?

Every inode has a hard link to at least a file. `unlink` will remove that hard link
between the inode and the file. When no links are attached to the inode, kernel will
remove it. So in other hand, `unlink` will remove a directory entry.
