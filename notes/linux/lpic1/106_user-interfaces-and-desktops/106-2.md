# Graphical Desktops

## Desktop Environments

When your system boots in the graphical mode, you will see a graphical login page. This
is based on the `X Display Manager Protocol(XDMCP)` which is responsible for the
underlying login system. It could be different programs that handle the theming and
other aspects of login like GDM(for GNOME) and SSDM(KDE).

After successful login, you will be in your GUI. Generally this is a large software
package which manages your windows, mouse, has clickable icons and folders with drag and
drop capability, and etc. These are called `Desktop Environments`. On the other hand
some prefer to have a minimal window manager without all the bells and whistles and
chose and add them based on their own preferences.

> :bulb: A window manager is responsible for showing and managing windows on your GUI.
> Even the most minimalist GUI, needs a window manager to be function. Add more and more
> libraries and software to your windows manager and you will end up with a Desktop
> Environment.

### GNOME

This is the only desktop environment I am using(till this day I am writing this). It
started at 1999, it focuses on productivity and accessibility. We will cover
accessibility in the next lesson. It is used by most GNU/Linux distros.

### KDE [Plasma]

It started at 1996. From version 5 (2016) re-branded to KDE Plasma. It is highly
customizable.

### XFCE

It started at 1999. It is lightweight and modular.

## Remote Connection to GUIs

There are many situations where you want to connect remotely to your GUI based system.
One of them happened in my last company, we have a certain situation in the country and
I couldn't connect to the VPN, so I should use one of these tools. At that time, I
wasn't educated on this topic, but hey, I am educating myself now:)!

### X Forwarding

This is not mentioned in LPIC 1 but it is super useful. X-Forwarding in SSH means to
connect to a SSH server and run GUI softwares there and ge the GUI part of the program
on your own machine and desktop.

First, make sure that the `X11Forwarding yes` is configured in the
`/etc/ssh/sshd_config`.

```bash
ssh -X root@1.1.1.1
xeyes
```

### VNC

Virtual Network Computer(VNC) started long time ago and it is still active and useful.
The good point of it is flexibility and clients on all platforms but it lacks security.

### Spice

The `Simple Protocol for Independent Computing ENvironment` started as closed source
software but become open source when RedHat bought company in 2008. It can be used to
connect to KVM virtual machines. It is the only use case for it for you(maybe not?).

### RDP

Using softwares like `Xrdp` you can start listening for `Remote Desktop Protocol`
connections on your own machine on port 3389 by default. The traffic is encrypted and
there are lots of free clients.
