# Customize and Use Shell Environment

## Environment Variables

Shell environment variables are special variables that contain information and
configuration about the shell.

```bash
env  # Show environment variables. printenv will do the same.
SHELL=/bin/bash
SESSION_MANAGER=local/ideapad:@/tmp/.ICE-unix/3218,unix/ideapad:/tmp/.ICE-unix/3218
QT_ACCESSIBILITY=1
COLORTERM=truecolor
XDG_CONFIG_DIRS=/etc/xdg/xdg-ubuntu:/etc/xdg
SSH_AGENT_LAUNCHER=gnome-keyring
no_proxy=localhost,127.0.0.0/8,::1
XDG_MENU_PREFIX=gnome-
GNOME_DESKTOP_SESSION_ID=this-is-deprecated
LC_ADDRESS=az_IR
GNOME_SHELL_SESSION_MODE=ubuntu
...

env FULL_NAME='Tomiako Giyu'
...
FULL_NAME=Tomiako Giyu
```

### set

`set` will allow you to change the values of shell options or display the names and
values of shell variables. It will display some functions too.

There are switches for the command too:

```bash
set -b  # Cause the status of terminated background jobs be reported immediately.
set -e  # Return in case a pipeline, command, etc return non-zero.
set -n  # Read commands but do not execute them. Used for checking syntax errors.
set -t  # Exit after reading and executing one command.
set -C  # Prevent output redirection from overwriting existing files.
```

## Setting Environment Variables

Bash environment variables naming is like Python variable namings. Traditionally we use
UPPERCASE letters in our variable names.

```bash
FULL_NAME='Tomiako Giyu'

echo $FULL_NAME
Tomiako Giyu
```

> Use `$` for referring the variable.

### unset

Use `unset` to remove the env variable.

### export

If you want that your parent shell(process) env variables be valid in the
sub-shell(sub-process), you have to export the variables.

### . and source

`.` is a shortcut for the bash to source the command. What do I mean by sourcing the
command? I mean executing and running the command in the current interactive shell, not
in a non-interactive sub-shell.

## Different Shell Envs

A shell can be started in 3 different ways:

- When you log into the shell, say after a ssh or when you site behind a terminal and
  login into a linux machine. This is an **interactive login session**.
- When you open a new terminal(say from a GUI). This is also an **interactive shell but
  not login shell**!
- And there are non-interactive shells. When your shell spawns new sub-shells to run a
  command, a non-interactive shell is used.

### Login Shell

This is where you enter your username and password to enter a shell. In this case, these
steps will define in your shell environment:

1. `/etc/profile` run.
2. A line in `/etc/profile` runs whatever is in `/etc/profile.d/`.
3. Now the global profile is loaded and system will go for user specific profiles: 3.1.
   Load `/home/USER/.bash_profile`. 3.2. Load `/home/USER/.bash_login`. 3.3. Load
   `/home/USER/.profile`. If any is loaded, the next ones are not going to be load.
4. Loads `/home/USER/.bashrc`.

> You know that you should put your custom configuration in the `~/.bashrc`.

### Interactive (non-login) shell

If you ran a shell in an interactive (non-login) shell, these file will handle the
environment:

1. `/etc/bash.bashrc` or `/etc/bashrc`.
2. `/home/USER/.bashrc`.

### Non-interactive Shell

No files are loaded. Instead we have the `BASH_ENV` which accepts a file that could be
loaded when a non-interactive shell starts.

## Few More Files

### /etc/skel

This directory is the skeleton of the `/home/` directories. When a new user home
directory is created, the system use this directory as a template.

### .bash_logout

Runs when you logout from the login shell.
