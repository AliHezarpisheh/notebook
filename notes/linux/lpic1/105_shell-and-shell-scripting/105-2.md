# Customize or Write Simple Scripts

## Combining Commands

If you want to run more than one command in one line, use `;`.

But using `;` is kinda lame. Mostly, we use `&&` or `||`. These are logical `and` and
`or`. So when you execute `cd /mydir && ls`, it will only go to the `ls` command if the
`cd /mydir` return in 0 status code. In the contrast, if you execute
`cd /home/ali/backup.sh || tar -cfg ...`, it will run until one of the commands exit
successfully. It is like the `and` and `or` in Python, but in the Linux/Unix context.

```bash
> cd ~ && ls
 Desktop   Documents   Downloads   Music   Pictures   Public   snap   Templates
 Videos  'VirtualBox VMs'

> cd /not-exist && ls
bash: cd: /not-exist: No such file or directory

> cd /not-exist || ls
bash: cd: /not-exist: No such file or directory
 Desktop   Documents   Downloads   Music   Pictures   Public   snap   Templates
 Videos  'VirtualBox VMs'

> cd /not-exist; ls
bash: cd: /not-exist: No such file or directory
 Desktop   Documents   Downloads   Music   Pictures   Public   snap   Templates
 Videos  'VirtualBox VMs'
```

> We use this kinda chaining to create logical flows.

## Shell Scripts

It is a text file that contains sequence of commands which are executed by the shell.
Useful when you want to automate tasks.

### Shebang

The first line of the scripts which starts with `#!` and continues with an executable
which is responsible for running the script. Even you can use python interpreter in the
shebang line! In shell scripts, I prefer to use `#!/usr/bin/env bash`, which make the
script portable across different unix-like systems. This ensures that the script runs
with the user's preferred or available version of Bash, regarding of its physical
installation location.

```bash
> vim script.sh

> cat script.sh
#!/usr/bin/env bash

echo
echo "My first formal shell script!"
echo


> chmod 755 script.sh

> ls -lrth script.sh
-rwxr-xr-x 1 root root 69 Jan  5 17:18 script.sh

> ./script.sh

My first formal shell script!
```

### Variables

Define variables as you seen before, `NAME=ali`.

```bash
> cat script.sh
#!/usr/bin/env bash

NAME='Ali'

echo "Hi my name is $NAME"

> ./script.sh
Hi my name is Ali
```

### Command Line Arguments

`$1` is the first command line argument. `$2` is the second one and so on. The `$#` is
the the number of command line arguments.

```bash
> cat script.sh
#!/usr/bin/env bash

echo "These are the first and second arguments: $1, $2"
echo "Total arguments numbers: $#"

> ./script.sh parasite "old boy"
These are the first and second arguments: parasite, old boy
Total arguments numbers: 2
```

## Executing Scripts

Inl Unix/Linux world, file should be executable to be executable! You already know how
to make a file executable using `chmod`. You already know that you can write the
interpreter of the files before the scripts. Also, you are aware of the `./script.sh`
thing. Why we use `./`?

Ok, let's get into the `exec` command. If you want to override and replace the current
shell with the shell that is assigned for the command you run, use the `exec` build-in
command. The `-c` switch will run the command in a clean environment.

## Command Substitution

You use command substitution when you want the output of a command inside a variable.
To do so you can use `$(command)` or \`command\`.

```bash
> FILES=$(ls -1)

> echo $FILES
nekoraylocalserver-12014670479469322708
postman-collections-post-response.instructions.md
postman-collections-pre-request.instructions.md ...

BACKUP_NAME="backup_"$(date +'%Y-%m-%d %H:%m:%S')

> echo $BACKUP_NAME
backup_2026-01-05 17:01:15
```

## Conditions

Let's bring some logic to our shell scripts. What are the two most preliminary tools for
adding logic to a programming language? Conditions and loops.

### if

Let's check the syntax:

```txt
if [condition]
then
  do something
  do another thing
else
  do new things
  even do more things
fi
```

> As you know, `else` is optional.

In python, the expression in front of a `if` statement should return a boolean value, or
be truthy or falsy. This is kinda the same in if commands in shell scripts.

```bash
if ["Linux" = "Linux"]
```

```bash
> cat script.sh
#!/usr/bin/env bash

kernel=$(uname -s)

if [ $kernel = "Linux" ]
then
  echo "Yyeyyyy, we are in linux"
  distro=$(cat /etc/os-release | grep -E ^ID= | sed 's/ID=//')
  echo "Distro name: $distro"
else
  echo "We are not in Linux:("
fi

> ./script.sh
Yyeyyyy, we are in linux
Distro name: ubuntu
```

The command to check the conditions is the `test` command but since it is used a lot, we
have a shortcut for it. Instead of `test condition` we can write `[ condition ]`.

| Conditions  | What it means?                                       | Result |
| ----------- | ---------------------------------------------------- | ------ |
| "a" = "b"   | If two strings are equal.                            | False  |
| "a" != "b"  | If two strings are not equal.                        | True   |
| 4 -lt 40    | Lower than.                                          | True   |
| 4 -gt 40    | Greater than.                                        | False  |
| 4 -le 40    | Lower than or equal.                                 | True   |
| 4 -ge 40    | Greater than or equal.                               | False  |
| 4 -ne 40    | Not equal.                                           | True   |
| -f FILENAME | If file FILENAME exists.                             | -      |
| -s FILENAME | If file FILENAME exists and its size is more than 0. | -      |
| -x FILENAME | If file FILENAME exists and it is executable.        | -      |

## read

Using `read` we can read the user input. Look at this:

```bash
> read NAME
ali

> echo $NAME
ali


> read -t 5 -p "What is your name: " NAME
What is your name: Ali

> echo $ALI


> echo $NAME
Ali

> echo $?
0
```

> Using `$?` you can inspect the exit code of the last command.

```bash
> cat script.sh
#!/usr/bin/env bash

if read -t 10 -p "What is the server ip: " SERVER_IP
then
  echo "Connecting to the server $SERVER_IP"
  exit 0
else
  echo "Sorry, too late..."
  exit 1
fi


> ./script.sh
What is the server ip: 127.0.0.1
Connecting to the server 127.0.0.1

> ./script.sh
What is the server ip: Sorry, too late...

> echo $?
1
```

## loops

In programming languages we use loops to repeatedly execute a block of code until a
specified condition is met.

We have two different types of loops in bash. `for` and `while`. You know what are they.

### for

Lets us run part of a program for a specific number of iterations.

```txt
for VAR in SOME_LIST;
do
  some stuff with $VAR
  some other stuff
done
```

```bash
> cat ../script.sh
#!/usr/bin/env bash

for NUM in 1 2 3 4 5;
do
  echo "Reading number: $NUM"
done

for NUM in $(seq 1 10);
do
  echo "Reading number from 'seq': $NUM"
done

for FILE_NAME in $(ls -1);
do
  FILE_LINE_COUNTS=$(wc -l $FILE_NAME)
  echo $"File $FILE_NAME has $FILE_LINE_COUNTS line numbers"
done;

> ../script.sh

Reading number from 'seq': 3
Reading number from 'seq': 4

Reading number from 'seq': 7
Reading number from 'seq': 8
Reading number from 'seq': 9

```

### while

Let us repeat part of a program while a specific condition became true.

```txt
while [condition]
do
  do something
  do another thing
done
```

```bash
> cat script.sh
#!/usr/bin/env bash

NUM=42

while [ $NUM -ge 38 ]
do
  let NUM=NUM-1
  echo $NUM
done

echo "Done"

> ./script.sh
41
40
39
38
37
Done
```

## Returned Values

In the Unix world, the programs return values when they are finished. Returning `0`
means the command is executed successfully. Use `$?` to examine the return value of the
last command.

```bash
> touch /chert
> touch: cannot touch '/chert': Permission denied

> echo $?
1

> touch /tmp/11

> echo $?
0

> test -e /

> echo $?
0

> test -e /nonexist

> echo $?
1

dummycommand
dummycommand: command not found

> echo $?
127
```

> Use `exit` in shell scripts. Use proper exit codes. This is a best practice.
