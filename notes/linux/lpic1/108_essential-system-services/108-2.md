# System Logging

One of the advantages of Linux is its logs. It generates logs in a way that gives you
enough observability for troubleshooting and understanding the system and services. Logs
are one of the most important parts of Unix philosophy and Design.

What is a log? A record which would give you insights of the working os, network, or
application.

Linux systems have a central logging system, preventing every app handles their logs in
their way. The applications send messages to device files such as `/dev/log` or
`/dev/kmsg`. The logging tool read from these devices and process the logs based on its
config. Finally the messages are turned into logs.

Historically, there were `syslog` and `syslog-ng` as the main management tools for log.
Now we have `rsyslog` and `journald` (as the `systemd` logging daemon). We have
`logrotate` for rotating log files and making our disk clean.

## dmesg and Kernel Ring Buffer

Logs should be stored on the disk, so what happens when there is no disk loaded at the
boot time? Kernel stores its logs in a place named `kernel ring buffer`, a memory in
Linux kernel which handles the log while the disk is not loaded.

Access kernel ring buffer through `dmesg`.

## Places Where Logs are Stored in the File System

Generally and most of the time, the logs are under `/var/log/`. Let's look at some
famous log files:

- **/var/log/auth.log**: The log file stores authentication-related events.
- **/var/log/syslog**: The centralized place most of the logs received by `rsyslog`. You
  could change it in the `/etc/rsyslog.conf` file.
- **/var/log/debug**: Debug logs.
- **/var/log/kern.log**: Kernel messages.
- **/var/log/messages/**: Default place for logs of remote clients.
- **/var/run/utmp & /var/log/wtmp**: Successful logins.
- **/var/log/btmp**: Failed logins.
- **/var/log/faillog**: Failed authentication attempts.
- **/var/log/lastlog**: Date and time of recent user loggings.
- **service logs**: They create their particular folder for logs in `/var/log`.

## Log Rotation

The best practice, in every context, from web applications to os systems, is to prevent
log files filling up the disk. We use log rotation to handle that.

The main tool for it is `logrotate` in Linux systems. It is managed in the
`/etc/logrotate.conf`.

```bash
root> cat /etc/logrotate.conf
# see "man logrotate" for details

# global options do not affect preceding include directives

# rotate log files weekly
weekly

# use the adm group by default, since this is the owning group
# of /var/log/syslog/
su root adm

# keep 4 weeks worth of backlogs
rotate 4

# create new (empty) log files after rotating old ones
create

# use date as a suffix of the rotated file
#dateext

# uncomment this if you want your log files compressed
#compress

# packages drop log rotation information into this directory
include /etc/logrotate.d

# system-specific logs may also be configured here.
```

Also, there are service-specific configurations at `/etc/logrotate.d/`:

```txt
/var/log/redis/redis-server*.log {
        weekly
        missingok
        rotate 12
        compress
        notifempty
}
```

`logrotate` use crons and do its job on the daily basis. The configuration is under
`/etc/cron.daily/logrotate`.

## rsyslog

The new generation of syslog. Like its ancestors, it stores logs in text format. The
configurations are under `/etc/rsyslog.conf` and it will read anything in the
`/etc/rsyslog.d/`.

The `rsyslog.conf` has three main sections:

- **Modules**: Modules used in syslog. For example you can make syslog use UDP
  connections by enabling its module.
- **Global Directories**: General configurations like directory access.
- **Rules**: A combination of facilities, priorities, and actions which tell syslog what
  to do with logs.

```txt
Common facilities are: kern, user, mail, daemon, cron, auth, ntp, security, console,
syslog, ...
```

```txt
The priorities are:
emerg/panic, alert, crit, err/error, warn/warning, notice, info or debug.
```

And these are the actions:

| Action   | Sample              | Meaning                                                                                                        |
| -------- | ------------------- | -------------------------------------------------------------------------------------------------------------- |
| filename | /usr/log/logins.log | Will write the log to this file                                                                                |
| username | ali                 | Will notify that person on the screen                                                                          |
| @ip      | @192.168.1.100      | Will send this log to this log server, and that log server will decide what to do with it based on its configs |

So a line like this will show the kernel panics to a remote log server and also will log
everything on every level to a log file:

```txt
kern.panic      @192.168.1.100
*.*             /var/log/messages
```

> If you need to log one specific level just put a `=` beside the priority. Like
> `local3.=alert`.

### klogd

The daemon logging the `kern` category is another daemon named `klogd`. Why? Because
when everything is crashed, `klogd` will be able to log the kernel crashes.

### logger

Use logger to send messages to syslog.

```bash
ali> logger "Hiii"

ali> tail -f -1 /var/log/syslog
Feb 18 19:38:53 ideapad ali: Hiii
```

## journald

We have seen how `systemd` has placed itself as one of the most important cores of Linux
ecosystem. We have seen how it handles init process, services, targets(runlevels in
SysVinit), timers( similar to cron jobs), and now we want to see how it handles logs.

All of the activities `systemd` manages and other logs reaching system journaling are
logged in binary files, readable by `journalctl` which is part of the `systemd-journald`

### journalctl

This is the command act as the main entry for working with the systemd journals. Here
are the useful switches:

| Switch            | Meaning                                                                                                                                                                                     |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| -r                | Show in reverse; newer on top                                                                                                                                                               |
| -f                | Keep showing the tail (follow new entries)                                                                                                                                                  |
| -e                | Show and go to the end                                                                                                                                                                      |
| -n                | Show this many lines from the end (newest ones)                                                                                                                                             |
| -k                | Show kernel messages (equal to dmesg)                                                                                                                                                       |
| -b                | Show from a specific boot. -1 is the previous one, 0 is the current one. Check list using `--list-boots`                                                                                    |
| -p                | Show from a specific priority, e.g., `-p err`                                                                                                                                               |
| -u                | Show from a specific systemd unit                                                                                                                                                           |
| --since / --until | Show a specific time range. Provide time as YYYY-MM-DD HH:MM:SS or use things like yesterday, today, tomorrow, now or even `--since "10 minutes ago"` (which equals `--since "-2 minutes"`) |

> If there are too many lines, push > to jump to the end (or < to go to the beginning).

You can use the executable or some fields like `PRIORITY` or `_PID` as other ways to
observer logs.

#### systemd-cat

Use it like `logger`, but it sends its input to the journaling system.

```bash
ali> echo "hi" > systemd-cat

ali> journalctl -f -n 1
Feb 18 20:58:29 ideapad unknown[748455]: hi
```

#### Managing Storage

The default storage management strategy of `journald` is:

- The system checks the `/var/log/journald/` and if the directory exists, logs will be
  saved in the directory named by the `/etc/machine-id`.
- If the directory does not exists, the logs will be saved in memory at
  `/run/log/journal` and in the directory named using the `/etc/machine-id`.

But the strategy can change based on the configuration. See the below config so you'll
have a sense of what we can change:

```txt
Storage=volatile     # keep the logs in memory
Storage=persistent   # keep on disk, if needed create the directories
Storage=auto         # will write to disk only if the directory exists
Storage=none         # do not keep logs
```

These are some configurations when you are storing logs on the disk:

| Variable Name     | Usage                                                                                            |
| ----------------- | ------------------------------------------------------------------------------------------------ |
| SystemMaxUse      | The maximum disk usage, e.g., `500M`. The default is 10% of the file system size.                |
| SystemKeepFree    | Keep at least this much free space, e.g., `1G`. The default is 15% of the file system size.      |
| SystemMaxFileSize | Maximum size of each individual log file. The default is 1/8 of `SystemMaxUse`.                  |
| SystemMaxFiles    | Maximum number of non-currently-active log files (archived/rotated) to keep. The default is 100. |

The equivalent of these variables when you are storing logs on memory is: `Runtime...`.

There are some switches for `journalctl` for removing old logs and freeing up disk
space.

| Switch         | Usage                                                                                                                                                                                            |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| --vacuum-time  | Clean everything older than this. For example `--vacuum-time=3months` cleans anything older than 3 months. You can use s, m, h for seconds, minutes, hours and days/d, weeks/w, months, years/y. |
| --vacuum-size  | Reduce logs until they occupy a specific size, e.g., `--vacuum-size=1G`.                                                                                                                         |
| --vacuum-files | Keep only this many archive files.                                                                                                                                                               |

#### Reading Logs of a Crashed System

By mounting the `/var/log/journal/{machine-id}` to somewhere in your live Linux, and
using switches of journalctl, you can read the logs of the machine:

- **D/--directory**: Giving a directory to journalctl to read logs from.
- **--merge**: Merge the specified log files to the system logs.
- **--file**: Observe the logs of a single file.
- **--root**: Telling the journalctl to search for the journal files from a specified
  place.

```bash
root> journalctl -D=/mnt/var/log/journal/ec22e43962c64359b9b25cfa650b025b/
```
