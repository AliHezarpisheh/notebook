# Maintain System Time

There is hardware clock in the computers which can be displayed and manipulated by the
`hwclock` on Linux systems:

```bash
ali> sudo hwclock
2026-02-06 13:29:41.222804+03:30

ali> sudo hwclock -u -w
```

Ok, as you can see, the hwclock command is not showing the utc time if it is set to the
utc. It automatically adds up to the time based on timezone, for seeing the actual
hardware time, you should see the `RTC time` entry in the `timedatectl` command.

It has its own battery and it is still working when the system is off. While booting,
the kernel will read the **hardware time** and set the **system time** based on it and
the timezone at `/etc/localtime`.

Checkout `/etc/adjtime` too:

```bash
cat /etc/adjtime

0.000000 1770372397 0.000000
1770372397
UTC
```

> There is a `/etc/timezone` file that holds the timezone info in text format. You can
> use it for programming purposes, but modify the `/etc/localtime` for modifying the
> timezone.

## NTP

**Network Time Protocol** is a protocol using ntp servers to find out accurate time
shown by atomic clocks. It is a protocol for clock synchronization between computers.

### ntpd

The older `ntp` daemon.

One of the first things we could do when there are issues in our system's clock is:

```bash
ali> sudo ntpdate pool.ntp.org
 6 Feb 18:02:49 ntpdate[74145]: adjust time server 131.188.3.222 offset +0.335305 sec
ali> sudo ntpdate pool.ntp.org
 6 Feb 18:03:06 ntpdate[74241]: adjust time server 131.188.3.222 offset +0.290326 sec
ali> sudo ntpdate pool.ntp.org
 6 Feb 18:03:16 ntpdate[74323]: adjust time server 131.188.3.222 offset +0.283241 sec
```

Every time you execute the command, it gets more precise. After it, you could set the
hardware clock with `hwclock -u`.

But instead of doing this manually, we could install the ntp service and start it.

ali> apt install ntp
