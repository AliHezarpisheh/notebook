## Passwords

### Changing Passwords

Each user can change her password using `passwd` command:

```bash
root> passwd postgres
New password:
Retype new password:
passwd: password updated successfully
root>
root> exit
exit

ali> su postgres
Password:

postgres>
```

> `passwd` command ask for the current password and refuse weak passwords, unless you're
> root. `root` can basically change anyone's password to anything.

Where and how the passwords are stored? First let's look at where the password seems
like they are stored, `/etc/passwd`.

```bash
tail -n 5 /etc/passwd
ali:x:1000:1000:ali,,,:/home/ali:/bin/bash
postgres:x:129:137:PostgreSQL administrator,,,:/var/lib/postgresql:/bin/bash
redis:x:130:138::/var/lib/redis:/usr/sbin/nologin
sshd:x:131:65534::/run/sshd:/usr/sbin/nologin
postfix:x:132:141::/var/spool/postfix:/usr/sbin/nologin
```

The format of each line is:

```txt
username:x:userid:primary group id:Name and Comments:home dir:shell
```

So, where are are the password. Historically, passwords were stored in `/etc/passwd`,
but because of security concerns, they have moved to the `/etc/shadows` and they are
replace with an `:x:` in `/etc/passwd`.

> :scroll: `/etc/passwd` is readable to all users and this makes it not a suitable place
> for storing passwords. The `/etc/shadow` is only readable and writable for the root.

Note that special users like `postfix` or `sshd` have /usr/sbin/nologin or /bin/false as
their shell. This prevents them logging.

#### /etc/shadow

This file contains hashed passwords for the users.

```bash
ali> ls -lrth /etc/shadow /etc/passwd
-rw-r--r-- 1 root root   3.1K Jan  7 15:22 /etc/passwd
-rw-r----- 1 root shadow 1.7K Jan  7 15:22 /etc/shadow

ali> tail /etc/shadow
tail: cannot open '/etc/shadow' for reading: Permission denied

ali> sudo tail /etc/shadow
[sudo] password for ali:
geoclue:*:19977:0:99999:7:::
pulse:*:19977:0:99999:7:::
gnome-initial-setup:*:19977:0:99999:7:::
hplip:*:19977:0:99999:7:::
gdm:*:19977:0:99999:7:::
ali:$y$j9T$wMtN9aG3Q9gbKY70sHLq61$17S/tLzf/fmf0KdBeA/2GLa9J6liP3ldzV9BgRPhif9:19982:0:99999:7:::
postgres:$y$j9T$BciqcVOpPspUfnxwodfJr/$WzMdwkduvQlvrXDIAu5hFsfG.WOKOgRJmMMxemJEYE.:20460:0:99999:7:::
redis:*:20003:0:99999:7:::

```

Ok, so postgres and ali has passwords. `*` means that there is no password for the user.

This is the format of each line:

```txt
username:hashed_password:when password changed(days after 1970):users won't be able
to change the password n days after each change:after these days user have to change the
password:user will be informed n days before his password expiration
```

> The numbers are days after `1st of January 1970` or the epoch time in days.

If should not change the `/etc/shadow` ourselves. There is a command named `chage` to
change these numbers. It is interactive.

```bash
ali> chage -l postgres
Last password change    : Jan 07, 2026
Password expires    : never
Password inactive   : never
Account expires   : never
Minimum number of days between password change    : 0
Maximum number of days between password change    : 99999

root@ideapad:~# chage postgres

Enter the new value, or press ENTER for the default

  Minimum Password Age [0]:
  Maximum Password Age [99999]:
  Last Password Change (YYYY-MM-DD) [2026-01-07]:
  Password Expiration Warning [7]:
  Password Inactive [-1]:

```

> :bulb: The `!` at first of the user's password in `/etc/shadow` means that the user's
> account is locked. You may also see `!!` means that the account has never been used.

## Users and Groups

Linux is a multi-user system and managing these users is part of the system admin's job.
You should be able to add, remove, and modify users at the first steps.

### Group

Linux has this concept of groups. You can define groups, give privileges to them and add
users to these groups. Use `chmod` and `chown` commands for giving privileges. You can
also add users to groups to give them some privileges. Each user can be a member of many
groups but it has only one primary group. In contrast, each file can be owned by just
one group.

### Managing Users

#### Adding users

To add a new user, you can use `useradd` or `adduser` commands. `adduser` is interactive
and asks the password and home directory, etc.

Switches for `useradd` command:

| Switch | Meaning                                      |
| ------ | -------------------------------------------- |
| -d     | Home directory.                              |
| -m     | Create the home directory.                   |
| -s     | Specify the shell.                           |
| -G     | Add to additional groups.                    |
| -c     | Comment. Most of the time, user actual name. |

```bash
root> useradd -m -d /home/elliot -s /bin/bash -G sudo -c "Ali's shadow account" elliot
root> passwd elliot
New password:
Retype new password:
passwd: password updated successfully

root> su elliot
To run a command as administrator (user "root"), use "sudo <command>".
See "man sudo_root" for details.

elliot> sudo apt update
[sudo] password for elliot:
Sorry, try again.
[sudo] password for elliot:
Hit:1 http://archive.ubuntu.com/ubuntu jammy InRelease
```

As said before, the files in the `/etc/skel` are copied in the new user's home
directory.

#### Modifying Users

To modify a user, you should use the `usermod` command. It supports most of the
`useradd` switches. There are more three switches too:

| Switch | Meaning                |
| ------ | ---------------------- |
| -L     | Lock this account.     |
| -U     | Unlock this account.   |
| -aG    | Append to more groups. |

```bash
root> su elliot

elliot> sudo apt update
[sudo] password for elliot:
Sorry, try again.
[sudo] password for elliot:
Sorry, try again.
[sudo] password for elliot:
sudo: 3 incorrect password attempts

elliot> exit
exit

root> usermod -U ellio
usermod: user 'ellio' does not exist

root> usermod -U elliot

root> su elliot

elliot> sudo apt update
[sudo] password for elliot:
0% [Waiting for headers]

root> groups elliot
elliot : elliot sudo

root> usermod -aG redis,postgres elliot
root> groups elliot
elliot : elliot sudo postgres redis
```

> If you do `usermod -G sudo elliot`, elliot will be the member of the `sudo` group
> ONLY. But with `-aG` the groups in front of the switch will be added to the user's
> current groups.

#### Deleting Users

Use `userdel`. Add the `-r` to remove the home directory and mail spool.

```bash
root> userdel elliot

root> sudo su elliot
su: user elliot does not exist or the user entry does not contain all the required fields

root> ls -lrth /home/
total 8.0K
drwxr-x---  2 1001 1001 4.0K Jan  7 15:05 elliot
drwxr-x--- 37 ali  ali  4.0K Jan  7 15:16 ali

root> rm -rf /home/elliot/
```

## Managing Groups

Use `groupadd`, `groupdel`, and `groupmod` for managing groups, like you use for the
users. Each group has an id and a name.

```bash
root> groupadd -g 1200 newgroup

root> getent groups | grep -i newgroup
Unknown database: groups

root> getent group | grep -i newgroup
newgroup:x:1200:
```

> If `root` delete a group, the members won't be deleted. They are not the member of the
> group anymore.

Where is the information about groups? They are in `/etc/group`.

```bash
ali> tail -n 5 /etc/group
vboxusers:x:139:
plocate:x:140:
postfix:x:141:
postdrop:x:142:
newgroup:x:1200:
```

> :bulb: In most systems, the user id or group id's of the users and groups created by
> the admin will have the id of >= 1000.

Theoretically groups can have passwords but it is never used in any distro, the file is
`/etc/gshadow`.
